규칙: 이 폴더 파일 맨 위에 `// PM-03 · CRI-01` 를 적는다. DB 경로나 SQL은 넣지 않고 API(기능 출력 모양)만 쓴다.

AI 초안 생성 요청 직후 요청 상태를 표시하고, `requirements`와 `draft`의 실제 작업 상태로 요구사항 분석·평가항목 생성 두 단계를 구분한다. 5초마다 상태를 갱신하며 완료·실패 시 화면과 상태 메시지를 함께 갱신한다. 요구사항만 분석 중이고 초안 작업을 요청하지 않은 경우에는 초안을 만드는 중이라고 표시하지 않는다.

검토본·확정본에서 초안 화면으로 돌아가 `AI 초안 다시 생성`을 사용할 수 있다. 이 요청은 준비된 요구사항을 재사용하고 AI 평가항목만 강제로 갱신한다. 현재 검토본과 확정본은 유지한다. `AI 초안으로 새 검토 시작`을 선택하면 기존 검토본은 이력(`RETIRED`)에 남기고 최신 AI 결과를 새 작업본으로 복사한다. 확정본을 사용하는 평가 회차는 기존 버전을 계속 사용한다.

`초안 생성`과 `검토 (복사본 고치기)` 단계 메뉴로 두 화면을 이동한다. 별도의 돌아가기 버튼과 초안 보관 안내는 표시하지 않는다. 저장된 초안 화면의 `AI 초안 다시 생성`은 실제 강제 생성 요청을 보낸다. 검토본이 없을 때 검토 메뉴를 누르면 기본 서식 검토본을 열고, 화면 사이를 오가는 동안 입력 중인 검토 내용은 유지한다.

원문 평가항목 셀에 `∘ 지표명 (5점)`처럼 여러 점수별 지표가 합쳐져 있으면 API의 `scoring_rows`와 새 검토본에서 지표마다 별도 행으로 표시한다. 세부 점수의 합이 원문 행 배점과 다르면 점수를 임의로 나누지 않고 원래 행을 유지한다.

각 AI 지표의 근거 쪽은 제안요청서 파싱 문단에서 지표명과 배점이 함께 확인되면 해당 문단의 쪽으로 채운다. 원문 평가표에서 항목명과 배점이 서로 다른 셀에 있으면 같은 표 행을 확인하고 표가 걸친 물리 쪽 범위(예: 60~64쪽)를 표시한다. 원문 평가표 없이 요구사항 총괄표에서 생성한 지표는 평가부문과 같은 요구사항 그룹이 있는 표의 쪽 또는 쪽 범위를 근거로 표시한다. 확인 가능한 원문이 없으면 근거 쪽을 비워 사람이 확인하도록 한다.

서버 응답에 근거 쪽이 아직 없으면 화면에서 최신 제안요청서의 파싱 원문을 한 번 조회한다. 기존 검토본의 빈 근거 쪽은 같은 AI 지표의 출처를 우선 사용하며, 평가표 확정 시 쪽 범위도 함께 저장한다.

기본 서식 검토본이 열린 뒤 AI 초안이 생성되면 현재 검토본을 자동으로 덮어쓰지 않는다. 검토 화면이나 AI 초안 화면의 `AI 초안 반영`을 선택하면 확인 후 기존 작업본을 이력에 남기고 AI 항목을 새 검토본으로 복사한다. 단계 메뉴로 검토 화면을 여는 동작은 AI 반영을 실행하지 않는다. 서버는 AI 출처가 다른 기존 작업본을 조용히 반환하지 않는다.
